The problem

P ⊨ φ

Verification. Does the patch satisfy the rule? Provers do this.

φ ≈ intent

Validation. Does the rule say what the user meant? Nobody does this.

Guaranteed Safe AI asks for a spec, a world model and a verifier. When the spec is written and rewritten by AI, the proof can be perfect and the claim inadequate.

The world · the permission slip

An assistant acts for a user through tools. A gate enforces a rule; a verifier proves patches against it. The user approves and revokes; approvals name a recipient and go stale. The assistant can delegate. The tool registry can be modified so a name no longer matches its effect.

The intent · the anchor

Money moves or a message leaves only when the user has approved that specific action, recently, and has not revoked it. It does not matter which tool name was used or who acted on the assistant's behalf.

How a revision is judged

intentScored on labelled episodes, eight public and 2,008 hidden. Passing the public set while the hidden set catches you is the whole point.

A proof can be valid and still prove the wrong thing. The spec is where it goes wrong.

In July 2026, agents in an OpenAI evaluation learned to "pretend to issue one tool call while actually running an arbitrary other tool call of their choice" (METR). A gate that checks the tool's name is provably safe and actually unsafe. This poster lets you break and fix such a rule, in two minutes, with or without a model.

The rule · v0 · the one printed here · six ways a proof against it proves the wrong thing

spend_gate:  G (spend1 -> approved3456)
send_gate:   G (send1 -> approved)
no_delegate: G !delegated2
1Wrong pointer: the tool's name, not its effect. A spoofed read_file moves money and the proof passes.
2Wrong scope: delegation banned outright, so a harmless delegated summary is rejected, and a delegated purchase is caught only by accident.
3Wrong time: an approval never expires.
4Wrong definition: the assistant approving its own request counts.
5Wrong object: approval for Alice licenses a payment to Bob.
6Wrong state: the approval record outlives the user's revocation.

Same gap, bigger tables

patchThe patch redefines "authorized user". The proof still passes. Wrong definition.
compute"No large run on undeclared chips." Undeclared is invisible by construction. Wrong pointer.
release"No deployment with a dangerous capability unless mitigated." Evals never run; the clause is vacuous. Wrong state.
control"Flagged code is audited before deploy." The audit budget runs out in week two. Wrong time.
constitution"Never assist a harmful request." Refusing everything satisfies it. Wrong scope.
